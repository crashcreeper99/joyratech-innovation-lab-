# 2026 Roadmap

The goal for the rest of 2026 is not to finish every ambitious idea. It is to establish a credible invention process and produce one evidence-backed prototype.

## Priority order

1. Keep coursework and academic deadlines stable.
2. Validate a real accessibility or connectivity problem with potential users.
3. Build small technical experiments that answer one question at a time.
4. Integrate the strongest experiments into one demonstrable prototype.
5. Document the evidence, limitations, and next steps.

## Phase 1 — Define and validate

**Outcome:** one narrow problem statement supported by real conversations.

- Write a one-sentence problem statement for each leading concept.
- Find at least five people who experience the problem or work closely with those who do.
- Conduct short, non-leading interviews using [USER_INTERVIEW_GUIDE.md](USER_INTERVIEW_GUIDE.md).
- Compare existing products, research, standards, prices, and limitations.
- Select one primary project using evidence, feasibility, safety, and learning value.
- Create a requirements list for a minimum viable demonstration.

**Decision gate:** do not begin a large integrated build until a specific user, problem, and measurable success condition are identified.

## Phase 2 — Reduce technical risk

**Outcome:** several small experiments, each answering one risky technical question.

Possible experiment categories:

- device discovery and profile detection;
- switching between two supported connection modes;
- input latency and reliability measurement;
- accessible input comparison using buttons, switches, voice, eye tracking, EMG, or other safe interfaces;
- simple companion-app communication;
- battery, power, enclosure, and usability tests.

For every experiment:

- state the question before building;
- define a pass/fail measurement;
- record parts, code, setup, and results;
- document failures honestly;
- keep unpublished novel implementation details private when appropriate.

## Phase 3 — Demonstrate one useful workflow

**Outcome:** a recorded prototype demonstration.

- Combine only the experiments required for one end-to-end use case.
- Test with representative users when safe and appropriate.
- Measure reliability, latency, usability, and failure modes.
- Record a short demonstration video.
- Publish a clear project update that distinguishes proven results from future goals.
- Write the next three engineering priorities.

## Definition of success by year end

- One validated problem statement.
- At least five user or expert conversations.
- One written requirements document.
- Three or more documented technical experiments.
- One narrow, repeatable prototype demonstration.
- One honest retrospective explaining results and next steps.

## Not a current goal

- Claiming universal compatibility before testing it.
- Attempting to decode unrestricted private thoughts.
- Building every project at once.
- Publishing patent-sensitive implementation details.
- Selling an untested prototype as a finished product.
