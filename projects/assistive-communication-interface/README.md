# Assistive Communication Interface

**Status:** user discovery and feasibility research

## Vision

Explore a low-effort communication interface for people who cannot type comfortably, quickly, or at all.

The project is not currently a device that reads unrestricted thoughts. A responsible early prototype should focus on intentional, user-controlled signals and a narrow set of communication actions.

## Problem to validate

Different users may be affected by limited motor control, fatigue, injury, speech differences, or temporary loss of access to conventional keyboards. Their needs and existing assistive tools vary widely, so the project must be shaped with users and accessibility professionals.

## Safer first direction

Start by comparing intentional input methods that can be evaluated without making medical claims, such as:

- large buttons or adaptive switches;
- limited gestures or head motion;
- eye-gaze interfaces;
- voice input where appropriate;
- surface EMG or other non-invasive signals with informed participation;
- word or phrase prediction controlled by a deliberate selection signal.

A first system might let a user choose among a small set of phrases, then expand only when reliability and consent are demonstrated.

## First useful demonstration

- one consenting test user or simulated accessibility scenario;
- a deliberate signal that selects among a small phrase set;
- visible confirmation before text is sent;
- a cancel action and an easy off switch;
- measured accuracy, selection time, false activations, and fatigue.

## Questions to answer

- Who specifically needs a lower-effort input method?
- What tools do they already use?
- Which failures are frustrating, unsafe, or privacy-invasive?
- What accuracy is necessary for a useful first version?
- How can the user remain in control of every transmitted message?
- Which experts or community organizations should guide the work?

## Safety, privacy, and ethics

- Obtain clear consent before collecting any physiological or behavioral data.
- Collect the minimum data required and define how it will be stored or deleted.
- Never present a prototype as a medical device or clinical solution.
- Make intended input visible and correctable.
- Test for false activation and provide immediate shutdown controls.
- Include users in design decisions rather than assuming their needs.

## Immediate next step

Interview potential users, caregivers, accessibility specialists, or speech-language professionals using the repository's interview guide. Select the first input method only after learning what problem actually needs solving.
